# تحلیلگر دوزبانه‌ احساسات و هیجان | Bilingual Sentiment & Emotion Analyzer

حس‌نما یک پروژه پردازش زبان طبیعی برای تحلیل متن‌های **فارسی و انگلیسی** است. سیستم از دو مدل مستقل مبتنی بر `DistilBERT multilingual` استفاده می‌کند: یک مدل برای قطبیت احساس متن (Sentiment) و یک مدل برای تشخیص هیجان غالب (Dominant Emotion). برنامه با FastAPI پیاده‌سازی شده و یک رابط کاربری تک‌صفحه‌ای سبک با HTML، CSS و JavaScript دارد.

> **وضعیت پروژه:** نسخه پژوهشی/دانشگاهی. خروجی مدل‌ها پیش‌بینی خودکار است و نباید به‌عنوان ارزیابی قطعی یا تحلیل روان‌شناختی تلقی شود.

## قابلیت‌ها

- پشتیبانی از متن فارسی و انگلیسی.
- تشخیص زبان ساده بر اساس وجود نویسه‌های خط عربی/فارسی؛ این روش برای متن‌های ترکیبی یا فینگلیش تضمین‌شده نیست.
- تحلیل Sentiment در سه کلاس `negative`، `neutral` و `positive`.
- تشخیص یک هیجان غالب از میان پنج کلاس `anger`، `fear`، `joy`، `sadness` و `surprise`.
- نمایش امتیاز تمام کلاس‌ها و امتیاز Softmax کلاس پیش‌بینی‌شده.
- رابط تک‌صفحه‌ای راست‌به‌چپ و واکنش‌گرا.
- اجرای inference روی CPU؛ برای استفاده از API نیازی به GPU نیست.

## اجرای محلی

### ۱. پیش‌نیازها

- Python 3.10 تا 3.13
- وزن‌ها و فایل‌های Tokenizer هر دو مدل در مسیرهای مشخص‌شده در پوشه `models`
- فایل‌های مدل از قبل آموزش‌دیده؛ اجرای API آموزش مجدد انجام نمی‌دهد.

### ۲. ساخت محیط مجازی

در پوشه اصلی پروژه اجرا کنید:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

اگر PowerShell اجازه فعال‌سازی محیط را نداد، می‌توان دستورهای نصب را با مسیر مستقیم ` .venv\Scripts\python.exe ` اجرا کرد.

### ۳. بررسی ساختار مدل‌ها

این دو مسیر باید وجود داشته باشند و شامل فایل‌های مدل و Tokenizer باشند:

```text
models/sentiment_multilingual_v1/
models/emotion_dominant_v1/
```

وزن‌های مدل حجیم‌اند و در مخزن Git معمولی قرار نمی‌گیرند. برای دریافت نسخه قابل اجرا از پروژه، باید وزن‌ها جداگانه و از یک منبع قابل اعتماد به این مسیرها منتقل شوند. پیش از انتشار عمومی، مجوز مدل پایه، داده‌ها و وزن‌های آموزش‌دیده نیز باید بررسی شود.

### ۴. اجرای سرور

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

سپس رابط کاربری را باز کنید:

- برنامه: <http://127.0.0.1:8000/>
- مستندات Swagger: <http://127.0.0.1:8000/docs>
- سلامت سرویس: <http://127.0.0.1:8000/health>

برای توقف سرور `Ctrl + C` را بزنید.

مقادیر پاسخ بالا صرفاً نمونه ساختار خروجی هستند و نتیجه ثابت یا تضمین‌شده برای متن ورودی محسوب نمی‌شوند.

محدودیت رابط کاربری و API برابر ۱۲۸ **کاراکتر** است. توکن با کاراکتر یکسان نیست؛ مدل‌ها ورودی را حداکثر تا ۱۲۸ **توکن** پردازش می‌کنند و در صورت عبور از این حد، متن در مرحله Tokenization کوتاه می‌شود.

## داده‌ها و روش آماده‌سازی

### Sentiment

- داده انگلیسی از TweetEval و داده فارسی از SentiPers تهیه شده است.
- برچسب‌های هر دو زبان به سه کلاس معنایی `negative`، `neutral` و `positive` نگاشت شده‌اند.
- برای متوازن‌تر شدن سهم دو زبان در آموزش، از ۱۰٬۵۴۹ نمونه انگلیسی و ۱۰٬۵۴۲ نمونه فارسی استفاده شد.
- مجموعه Validation شامل ۳٬۳۴۵ نمونه و برای انتخاب نسخه مدل استفاده شد.
- ارزیابی نهایی بر روی فایل‌های تمیز `test.csv` انجام شده است؛ فایل‌های `test_official.csv` مبنای ارزیابی اصلی نیستند.

### Dominant Emotion

- منابع مورد استفاده شامل GoEmotions، EmoPars و ArmanEmo هستند.
- پنج کلاس مشترک پروژه عبارت‌اند از anger، fear، joy، sadness و surprise.
- در GoEmotions، نمونه‌هایی نگه داشته شدند که دقیقاً یک برچسب فعال از میان پنج کلاس منتخب پروژه داشتند؛ ممکن است در برچسب‌گذاری اصلی، برچسب‌های دیگری خارج از این پنج کلاس نیز وجود داشته باشند.
- در EmoPars، آستانه رأی اکثریت (حداقل ۳ رأی از ۵ رأی) به‌کار رفت. `Happiness` به `joy` و `Wonder` به `surprise` نگاشت شده است؛ این نگاشت آخر تقریبی است. برچسب `Hatred` در این نسخه کنار گذاشته شد.
- در ArmanEmo، کلاس‌های `ANGRY`، `FEAR`، `HAPPY`، `SAD` و `SURPRISE` به پنج کلاس پروژه نگاشت شدند و `HATE` و `OTHER` کنار گذاشته شدند.
- مجموعه ArmanEmo جداگانه برای ارزیابی نگه داشته شد؛ چون از همان منبعی است که بخشی از داده آموزش فارسی از آن می‌آید، نباید آن را ارزیابی مستقلِ بین‌منبعی یا cross-source نامید.

## نتایج ارزیابی

معیار اصلی گزارش، Macro-F1 است. برای نتیجه دوزبانه، میانگین Macro-F1 زبان انگلیسی و فارسی به‌صورت جداگانه محاسبه شده تا اندازه بزرگ‌تر یک مجموعه بر دیگری غلبه نکند.

### Sentiment — مجموعه Test

| معیار | انگلیسی | فارسی |
|---|---:|---:|
| Macro-F1 | 61.86% | 67.82% |

- Balanced-language Macro-F1: **64.84%**
- Combined Accuracy: **63.67%**
- Combined Macro-F1: **63.39%**

### Dominant Emotion — مجموعه اصلی Test

- Overall Accuracy: **63.30%**
- Overall Macro-F1: **63.48%**
- English Macro-F1: **83.16%**
- Persian Macro-F1: **28.54%**
- Balanced-language Macro-F1: **55.85%**

### Dominant Emotion — مجموعه نگه‌داشته‌شده ArmanEmo

- Accuracy: **55.77%**
- Macro-F1: **56.22%**

عملکرد Emotion در دو زبان یکسان نیست و نتیجه فارسی روی مجموعه اصلی Test ضعیف‌تر است. این تفاوت باید در تفسیر نتایج لحاظ شود. همچنین منابع داده زبان‌ها متفاوت‌اند؛ بنابراین اثر زبان را نمی‌توان به‌طور کامل از اثر منبع و حوزه داده جدا کرد.

## محدودیت‌ها

1. تشخیص زبان مبتنی بر نویسه است و برای متن‌های ترکیبی، فینگلیش، نام‌ها یا متن کوتاه ممکن است اشتباه کند.
2. مدل Emotion فقط یک هیجان غالب از پنج کلاس تعریف‌شده را برمی‌گرداند؛ این مدل چندبرچسبی نیست و همه هیجان‌های حاضر در متن را استخراج نمی‌کند.
3. Softmax confidence معادل احتمال کالیبره‌شده صحت پیش‌بینی نیست و نباید به‌عنوان تضمین درستی تعبیر شود.
4. هر دو مدل به حداکثر طول ۱۲۸ توکن محدودند؛ رابط و API نیز ورودی را به ۱۲۸ کاراکتر محدود می‌کنند.
5. عملکرد مدل‌ها به کیفیت، توازن و دامنه داده‌های آموزشی و ارزیابی وابسته است. خروجی‌های نادرست، از جمله اشتباه در تشخیص هیجان متن‌های مبهم یا کوتاه، محتمل‌اند.
6. امتیازهای زبان‌های مختلف تحت تأثیر تفاوت منابع و نوع متن‌ها نیز قرار دارند.

## آموزش و ارزیابی مجدد

اسکریپت‌های اصلی در ریشه پروژه قرار دارند. آموزش مجدد ممکن است به حافظه و توان پردازشی قابل توجه نیاز داشته باشد؛ برای استفاده عادی از برنامه لازم نیست این دستورات اجرا شوند.

```powershell
# Prepare dominant-emotion data (only if raw source files are present)
python prepare_dominant_emotion.py

# Train the two models
python train_sentiment.py
python train_dominant_emotion.py

# Evaluate on the clean held-out test files
python evaluate_sentiment.py
python evaluate_dominant_emotion.py
```

برای بازتولید دقیق نتایج، نسخه داده‌ها، تنظیمات آموزش، نسخه کتابخانه‌ها و فایل‌های گزارش باید حفظ شوند. مجموعه Test نباید برای تنظیم مکرر مدل یا انتخاب Hyperparameter به‌کار رود.
